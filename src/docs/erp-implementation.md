# ERP Lesson: Implementation

Most ERP projects follow these phases: discovery and requirements, design with a fit-gap analysis (what the standard software does versus what the business needs), configuration, data migration, testing including user acceptance testing (UAT), training, go-live, and support afterwards.

Go-live choices: big bang switches everyone at once; phased rollouts go module by module or site by site, which lowers risk but takes longer; parallel running keeps the old system alongside for a while.

Common reasons projects struggle: poor data quality (dirty customer, supplier and item records), scope creep, too much customisation, weak executive sponsorship, and people not being trained or not accepting the change.

Good practice: clean the master data before migrating, keep customisation low and use standard processes where possible, name a business owner for each process, test with real scenarios, and plan for change management, not just technology.
